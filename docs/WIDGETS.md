# Widgets (Build 29)

Zalla ships a WidgetKit extension, `ZallaWidgets`, with four widgets. Everything for it lives in `ZallaWidgets/`, `Shared/`, `config/`, and the `ZallaWidgets` target in `project.yml`, plus `WidgetSync.swift` and `WidgetsSettingsView.swift` in the app. It went in as its own commit so reverting that commit removes widgets cleanly.

## What the widgets are

| Widget | Sizes | Tap |
| --- | --- | --- |
| Search | small, medium, Lock Screen circular and rectangular | `zalla://search` (focuses the address bar) |
| Favorites | medium (up to 4), large (up to 8) | each tile opens that site in a new tab (`zalla://open?url=...`) |
| Burn It All | small | `zalla://burn` (opens the confirmation, never burns) |
| Privacy Report | small, medium, Lock Screen rectangular | opens Zalla |

All use `AppIntentConfiguration` (iOS 17). In the widget editor a person can pick the color (follow Zalla or a fixed one), the look (filled or soft), and for Favorites the source (home shortcuts or bookmarks), how many, and whether titles show.

Zalla has no counter for blocked trackers, so Privacy Report shows what Zalla does count: links cleaned, HTTPS upgrades, and cookie banners closed. Before the app has written anything it shows a plain call to action.

## How data gets there

1. `WidgetSync.refresh` (app) builds a `WidgetSnapshot` (`Shared/WidgetSnapshot.swift`): accent hex, home shortcuts, bookmarks, Privacy Report totals. Only http and https addresses are kept, titles are trimmed, lists are capped at 8.
2. It is written as JSON to the shared `UserDefaults(suiteName: "group.com.zalla.browser")` under `widgetSnapshot`, only when the content changed, then `WidgetCenter.shared.reloadAllTimelines()` runs. This happens at launch and whenever Zalla leaves the foreground.
3. The extension only reads it (`ZallaEntry.make`). Timelines hold one entry and ask for a refresh after 6 hours as a safety net.

Not shared, ever: history, open tab addresses, anything from a private tab, search text. The extension has no networking code. Settings, Tools, Widgets, "Share with widgets" (`widgetsShareData`, default on) off erases the snapshot and the widgets show empty states. Reset Zalla erases it too.

## Manual steps in the Apple Developer portal (before the next TestFlight build)

Until these are done, the TestFlight workflow cannot sign this build, for the app or the extension.

1. Certificates, Identifiers and Profiles, Identifiers, App Groups: register `group.com.zalla.browser`.
2. Identifiers, App IDs: register a new App ID `com.zalla.browser.widgets` (explicit, description "Zalla Widgets").
3. Open the App ID `com.zalla.browser`, enable the App Groups capability, Configure, tick `group.com.zalla.browser`, save.
4. Open `com.zalla.browser.widgets`, enable App Groups, tick `group.com.zalla.browser`, save.
5. Profiles: changing capabilities invalidates the existing App Store profile for `com.zalla.browser`. Edit it (or delete it and create a new one) so it is valid again, then create a new App Store Connect (distribution) profile for `com.zalla.browser.widgets` with the same distribution certificate.
6. In Codemagic, Team settings, codemagic.yaml settings, Code signing identities, iOS provisioning profiles: fetch the two new profiles from the portal. `codemagic.yaml` is unchanged on purpose: `ios_signing` with `bundle_identifier: com.zalla.browser` already picks up uploaded profiles for `com.zalla.browser` and `com.zalla.browser.*`, so the extension's profile is found by its bundle ID and `xcode-project use-profiles` applies it.
7. Start a TestFlight build by hand (nothing starts one automatically).

Default browser entitlement is a separate, later task: `docs/DEFAULT_BROWSER.md`. Do not add it to the profile before Apple approves it.

## If signing fails and you need to ship without widgets

Revert the widgets commit. That removes the `ZallaWidgets` target, the `Shared/` folder, the App Group entitlements, `WidgetSync`, and the Settings screen. Quick actions, default browser preparation, and Video Saver are in the earlier commit and stay.

## Build notes

- `Shared/` is a source folder of both targets (it is compiled twice, once into the app and once into the extension). Keep `WidgetSnapshot.swift` Foundation only and `WidgetViews.swift` SwiftUI only (no WidgetKit) so both compile.
- Entitlements files (`config/Zalla.entitlements`, `config/ZallaWidgets.entitlements`) are generated by `xcodegen generate` from `project.yml`.
- The extension shares the app's marketing and build numbers (`CURRENT_PROJECT_VERSION`), as App Store validation requires. `agvtool new-version -all` in `codemagic.yaml` updates both.
- Simulator builds use `CODE_SIGNING_ALLOWED=NO` and need none of the portal setup.
