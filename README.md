# Zalla

**Built around you.** A free, privacy-conscious iPhone browser, with a one-time Zalla Unlock of about $2 (the price shown in the App Store is the one that applies).

## Current milestone

Native SwiftUI + WKWebView foundation targeting iPhone on iOS 17+. This is early source code, not an App Store-ready or device-verified build. No Swift compiler, iOS simulator, or Xcode is available in the originating Windows workspace.

Implemented in source:
- Address/search input, back/forward gestures and buttons, reload/stop, progress and error messages.
- Multiple regular tabs and private tabs with separate nonpersistent website stores.
- Local bookmarks and history (most recent 500 unique URLs); private visits excluded.
- Native page sharing and confirmed telephone, SMS, and email handoffs.
- Red-accent start page, local favorites, system/light/dark appearance, three search engines.
- Clear history and website data, closing tabs before deletion; bookmarks retained.
- App-switcher privacy cover; device-protected library file excluded from OS backup.

## Build 27

- Status bar strip follows the page's real top edge (`PageColor.swift`, `BrowserStore.swift`, `BrowserView.swift`). Feedback on Builds 23 to 26 was that the top looked wrong while scrolling and should behave like a normal website, with the strip behind the clock matching the page (Reddit black header, YouTube dark header). No site-specific code existed or was added; the page layer still behaves as a plain web view. The page script (`PageColor.script`) now samples what is painted: `elementFromPoint` at five x positions just below y = 0, walking up ancestors to the first background that paints (rgba and space-separated alpha handled, an image or gradient stops the walk and falls back), most common color wins. Fallback order is edge, theme-color (first tag whose media query matches, so dark mode tags work), body, html (a `color-scheme: dark` page with no background counts as `rgb(18, 18, 18)`), then white. It re-reads on load, DOMContentLoaded, pageshow, resize, orientation change, transitionend, scroll (a requestAnimationFrame read at most every 100 ms plus a 120 ms trailing read), a throttled MutationObserver (head tags, html and body class and style, body children for single page app swaps), prefers-color-scheme changes, and a 1 s check while visible. It only posts when the edge moved by 6 of 255 per channel or another field changed, and the payload now carries `edge` and `ready` (document.readyState is complete).
- Native side (`PageInfo.edgeBackground` and `ready`, both defaulted so existing calls compile). `PageColor.next(current:info:)` keeps the previous color when a page still loading reports nothing usable, so there is no white flash on navigation (the previous page color is kept until a real sample arrives; nothing resets to white or red). `PageColor.differs` ignores shifts under 0.012 per channel. The strip fade is 0.15 s (Reduce Motion: none).
- Clock and battery text: `PageColor.isDark(_:previous:)` has hysteresis (dark below luminance 0.14, light above 0.22, otherwise keep the last choice), stored as `BrowserTab.pageColorIsDark` and passed to `PageColor.plan(... isDark:)`. The app-wide System appearance flip (`preferredColorScheme`) is kept, since SwiftUI offers no status bar style only switch without a hosting controller subclass, but a switch between light and dark now waits 200 ms (`appliedStatusBarScheme`, `.task(id:)`), and going to or from no override is immediate.
- Frame: the Build 24 behavior stays (the web view starts below the strip, so fixed and sticky headers sit under the clock like Safari). New: while the strip is painted, `webView.underPageBackgroundColor` is the strip color, so rubber banding past the top shows the page color, not a gap.

## Build on a Mac

1. Install Xcode with the iOS SDK and XcodeGen (https://github.com/yonaskolb/XcodeGen).
2. In this folder run `xcodegen generate` and open `Zalla.xcodeproj`.
3. Select the Zalla scheme and an installed iPhone simulator; build and run.
4. Run the ZallaTests target with Product → Test.
5. For a physical iPhone, choose your Apple development team in Signing & Capabilities and replace the placeholder bundle identifier with one you control.

The project specification generates Info.plist. The web-content-only App Transport Security exception permits user-requested HTTP websites; native app network requests retain platform defaults. TLS failures use WebKit's default handling. The [icon kit](docs/branding/icons/README.md) includes a configured app icon catalog, appearance variants and development exports; Mac/device validation and native Icon Composer adoption remain release work. Default-browser entitlements, signing, and App Store metadata are intentionally still release work.

See [product direction](docs/PRODUCT.md) and [device validation](docs/VALIDATION.md). The original project handoff remains unchanged.
